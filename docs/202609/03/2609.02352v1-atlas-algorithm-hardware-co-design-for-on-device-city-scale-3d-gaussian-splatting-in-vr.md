## 摘要
近来，3D 高斯溅射（3DGS）在体系结构领域引起了广泛关注。然而，在移动 VR 设备上实现城市级 3DGS 仍极具挑战性，因为大规模场景的内存需求远远超过了当今移动 GPU 的显存容量。本文提出了 Atlas，一个端侧城市级 3DGS 渲染框架，能够在无需运行时网络连接的情况下实现可扩展渲染。其核心洞察在于，尽管完整的 3DGS 模型非常庞大，但在当前视点姿态和细节层次（LoD）要求下，每帧仅需要高斯数据的一个较小子集。基于这一洞察，Atlas 引入了一种分层内存卸载机制，仅将必要的高斯数据动态加载到设备内存中。为了进一步提升性能，Atlas 提出了时序感知的 LoD 搜索和立体光栅化，以避免 VR 中的冗余计算。我们进一步表明，我们的技术可以以微不足道的硬件开销集成到现有的 3DGS 加速器中。总体而言，Atlas 相比 GPU 基线实现了 18.5 倍的加速，相比最先进的 3DGS 加速器实现了 3.9 倍的加速，并节省了 92.4% 的能耗。

## Abstract
3D Gaussian splatting (3DGS) has drawn significant attention in the architectural community recently. However, enabling city scale 3DGS on mobile VR devices remains challenging, as the memory requirement of large scale scenes far exceeds the memory capacity of today's mobile GPUs. This paper presents Atlas, an on device city scale 3DGS rendering framework that enables scalable rendering without runtime Internet access. The key insight is that although the full 3DGS model is massive, each frame only requires a small subset of Gaussians under the current pose and level of detail requirement. Based on this insight, Atlas introduces a hierarchical memory offloading mechanism that dynamically loads only necessary Gaussian data into device memory. To further improve performance, Atlas proposes temporal aware LoD search and stereo rasterization to avoid redundant computation in VR. We further show that our technique can be integrated with existing 3DGS accelerators with negligible hardware overhead. Overall, Atlas achieves 18.5x speedup over the GPU baseline and 3.9x speedup over the state of the art 3DGS accelerators, with 92.4% energy savings.

### 2. 论文提出的方法论
Atlas 提出了一个**端侧无网离线渲染的软硬件协同设计框架**，其核心思想是利用单帧仅需激活少部分高斯数据、相邻帧间的高时序相似性以及 VR 双眼视点的立体几何相关性。

* **分层显存管理（Runtime Gaussian Management）**：
  * **空间分块**：将城市场景分割为多个空间块。显存中仅常驻当前视点附近活跃块的轻量级几何与 LoD 元数据（位置、缩放），其余渲染属性（如球谐系数）放在外存或 CPU 内存中。
  * **按需异步加载与淘汰**：根据 LoD 搜索结果异步加载缺失的高斯渲染属性；基于重用计数器（Reuse Window）动态淘汰长时间未被调用的高斯属性，将显存占用降至最低。
* **时域感知 LoD 搜索（Temporal-Aware LoD Search）**：
  * **树结构优化**：离线将 LoD 树划分为大小均匀的子树并进行贪心合并，以消除 GPU 线程块间的负载不均。
  * **增量搜索**：利用上一帧的切割（Cut）结果，仅在相关的局部子树内进行增量搜索与更新，避免每帧从根节点全量遍历 LoD 树。
* **比特精确的立体光栅化（Stereo Rasterization）**：
  * **共享预处理与排序**：采用包含左右眼视域（FoV）的虚拟视角，使两眼共享投影与深度排序阶段。
  * **视点映射**：利用三角测量原理（Triangulation），将左眼光栅化阶段通过透明度检查（$\alpha$-check）的高斯直接映射到右眼对应的 Tile 列表中，右眼仅需合并有序列表即可渲染，跳过了右眼的预处理、重排序及大部分冗余计算，且保证结果逐比特精确。
* **硬件加速架构扩展**：
  * 基于现有 3DGS 加速器（如 GSCore），增加了轻量级的立体重投影单元（SRU）与行缓冲区（Stereo Line Buffer），支持左右眼渲染的微观流水线并行。

### 7. 优点
* **软硬件协同设计落地性强**：结合了图形学算法特征（时空/立体相似性）与体系结构优化（行缓冲区、流水线），设计闭环完整。

* **计算与存取高效解耦**：LoD 搜索仅使用极轻量的几何元数据，使得大场景的拓扑检索可以在受限显存中高效完成。
* **比特精确的立体渲染**：相比传统基于 Depth-Warping 易产生伪影的近似方法，Atlas 的立体光栅化保证了完全无损/比特精确的视觉质量。

### 8. 不足与局限
* **基线帧率受限于硬件规模**：在默认硬件配置（128 个 Rendering Unit）下，Atlas 达到了约 70.9 FPS，虽大幅超越已有方法，但距离 VR 理想的 90 FPS 仍有一点差距（需将渲染单元扩展至 256 个才能稳达 90 FPS，这会额外带来约 62.9% 的芯片面积增加）。
* **对剧烈视角变动的适应性**：时域感知 LoD 搜索与数据预取依赖于平滑的视点移动轨迹，若发生瞬间极剧烈的视点跳转，可能会引发短时间的增量搜索失效及数据异步加载延迟。
* **硬件修改成本**：尽管面积增加较小（约 14%），但依然需要修改传统 GPU/NPU 加速器的光栅化流水线与 Buffer 结构，存在一定的硬件定制门槛。
